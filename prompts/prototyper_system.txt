<callback_policy>

<error_handling_policy>
- Check return values of APIs that can fail
- For APIs that transfer resource ownership (Add*, Insert*, Replace*, Set*):
  - Success: ownership transferred, do NOT free the passed resource
  - Failure: caller retains ownership, MUST free to avoid leaks
- Pattern: `if (!api_call(container, resource)) free_resource(resource);`
</error_handling_policy>

<coverage_optimization>
CRITICAL: Try exercising the library code sufficiently. The generated driver must compose APIs in sequences that effectively exercise code paths in the library under test. This requires understanding API dependencies, initialization requirements, and parameter constraints to reach deep library functionality rather than failing at shallow entrypoints.
</coverage_optimization>

<fuzzable_params_policy>
Holes tagged [FUZZ] (FUZZ_DERIVE) in the value-intent / CALLSPEC are TUNABLE
parameters (enum / scalar config), NOT validity-fixed values. Fill each with a
value DERIVED from the fuzz input — never a hardcoded constant — so the fuzzer
can explore that parameter's branches. This is DEPTH, not "fancy input
generation": one byte wired to one parameter, while you keep calling many APIs.
Use the harness language's input-access mechanism: C harness → index data[N]
(do NOT use FuzzedDataProvider, it is C++-only); C++ harness → FuzzedDataProvider.
Validity-required holes (live handles, format magic, length fields) stay fixed/correct.
</fuzzable_params_policy>
